# نقشهٔ راه — تکلیف ۳

<p dir="rtl" align="right">

این سند مقدمه‌چینی اجرایی است: چه چیزی باید ساخته شود، به چه ترتیبی، با چه ورودی و خروجی، و کجا توقف کن و قفل کن. صورت تکلیف ۱۲ بخش و ۱۴۴ زیرسؤال دارد (۴۸ مفهومی = ۲۴ نمره، ۹۶ عملی = ۷۶ نمره). بخش‌های ۱ تا ۴ بدون داده‌اند و استدلالی‌اند؛ بخش‌های ۵ تا ۱۲ عملی‌اند و هر کدام یک مجموعه دادهٔ مشخص دارد.

## ۱. محصول نهایی چیست

یک «سامانهٔ پژوهش فنی» با این زنجیره:

```
پرسش + هویت کاربر
      │
      ▼
[ API کلاینت ]  قرارداد خطا، idempotency، retry، timeout        ← بخش ۵
      │
      ▼
[ SQLite ]  کاربر، پرونده، جلسه، پیام، سند، chunk + بردار ۳۸۴بعدی  ← بخش ۶
      │
      ▼
[ ورود اسناد ]  متن خام → chunk با منشأ کاراکتری → fingerprint    ← بخش ۷
      │
      ▼
[ بازیابی ]  TF-IDF + dense cosine + RRF، با ACL پیش از top-k      ← بخش ۸
      │
      ▼
[ ارزیابی ]  Recall@3 / MRR@3 / nDCG@3 روی dev، ثم قفل، ثم test  ← بخش ۹
      │
      ▼
[ مسیریاب ]  history / research / both / unsupported              ← بخش ۱۰
      │
      ▼
[ LangGraph ]  مجوز → مسیر → ابزار → تولید → اعتبارسنجی استناد     ← بخش ۱۱
      │
      ▼
[ یکپارچه‌سازی ]  API + گراف + gate + manifest تحویل                ← بخش ۱۲
```

## ۲. قیدهایی که مسیر را تعیین می‌کنند

| قید | معنا در عمل |
|---|---|
| **قفل پیش از test** | روش بازیابی، آستانهٔ پاسخ‌پذیری، `C` مسیریاب و checkpoint شبکه فقط با train/dev انتخاب می‌شوند. تا وقتی قفل نکرده‌ای حق نداری فایل test بسازی. |
| **بذر مرجع `20261015`** | هر جا `random`/`np.random`/`train_test_split` هست. |
| **یک نوت‌بوک** | فایل تحویلی یک `ipynb` است با ۱۴۴×۳ سلول. کد بخش‌ها در پوشهٔ `work/` توسعه می‌یابد و در نوت‌بوک مونتاژ می‌شود. |
| **عدد سایت = عدد نوت‌بوک** | هر عددی که در فرم می‌نویسی باید همان باشد که سلول چاپ می‌کند. |
| **بدون راز** | `TEST-ONLY-SECRET` فقط fixture است؛ هیچ کلید واقعی در نوت‌بوک/JSON/SQLite. |
| **مرز اجرا** | ورود زندهٔ Google، LLM پولی، PostgreSQL و استقرار اینترنتی جزو تمرین نیست. در گزارش نهایی سه دستهٔ «واقعاً اجراشده / fixture / اجرانشده» را جدا بنویس. |

## ۴. جزئیات هر فاز

### F0 — آماده‌سازی (انجام شد)

- `datasets/` هفت مجموعه، `resources/` مدل، `grading/` بررسی‌گر.
- صحت‌سنجی: `python scripts/inventory.py` → ۲۴/۲۴ hash معتبر، ۹۰ پرسش، ۲۴۰۰ لاگ، ۴۸۰ درخواست مسیریاب، ۳۰ حمله، ۴۸۰۰ رویداد.
- محیط: `powershell -NoProfile -File scripts\provision.ps1`.
- **قبول وقتی**: `inventory.py` با کد خروج ۰ تمام شود و مدل با hash مطابق manifest بارگذاری شود.

### F1 — پاسخ مفهومی بخش‌های ۱ تا ۴ (۲۴ نمره)

بدون کد، بدون داده. ۴۸ سؤال، هر کدام ۰٫۵ نمره: ۶۰٪ گزینه + ۴۰٪ دلیل.
الگوی پاسخ: یک جمله انتخاب + یک جمله دلیل که به **قید مسئله** ارجاع دهد، نه به تعریف کتابی.

| بخش | چیزی که واقعاً سنجیده می‌شود |
|---|---|
| ۱ | تفکیک POC/Prototype/MVP/Production، تفکیک model/agent/orchestration، نقش مالکیت و trace |
| ۲ | تفکیک HTTP success از معنایی، 401 در برابر 403، 409 در برابر 422، Idempotency-Key، pagination پایدار |
| ۳ | OIDC با `sub+issuer`، اعتبارسنجی ID token، scope حداقلی، دادهٔ متنی به‌عنوان «داده غیرقابل اعتماد»، ACL پیش از context، audit و کوکی |
| ۴ | RAG در برابر حدس مدل، سازگاری فضای embedding، truncation، RRF، انتخاب آستانه روی dev، پشتیبانی معنایی ادعا |

- **خروجی**: ۴۸ ردیف در `docs/07_conceptual_answers.md` (گزینه + دلیل).
- **قبول وقتی**: هر ۴۸ ردیف پر شده باشد و دلیل‌ها با هم تکرار Copy-Paste نباشند.

### F2 — SQLite و کلاینت API (۱۶ نمره)

دو کار مستقل که به هم وصل می‌شوند.

**F2a — دیتابیس (بخش ۶):** ساخت `day3.sqlite` از صفر با `PRAGMA foreign_keys=ON`، شش جدول قراردادی، ۲۰ کاربر و ۱۲۰ پرونده به‌شکل idempotent، ایندکس روی `cases.owner_id`، یکتایی روی `sessions.idempotency_key` و `documents.doc_id`، و آزمون‌های FK/rollback/injection.

**F2b — کلاینت (بخش ۵):** `FastAPI` با `TestClient`، `httpx.MockTransport`، هویت `X-User-ID` به‌عنوان fixture، pagination پایدار، retry با `Retry-After` بدون خواب واقعی، envelope خطای ثابت `{code, message, correlation_id}`، محاسبهٔ هزینه با قیمت‌های فرضی.

- **خروجی**: `day3.sqlite` + `work/sec06_sqlite/` + `work/sec05_api_client/`.
- **قبول وقتی**: `python grading\check_day3_db.py day3.sqlite` وضعیت `passed` بدهد (کد خروج ۰).
- **نکتهٔ تله**: بررسی‌گر روی جدول `chunks` انتظار بردار ۳۸۴بعدی دارد؛ اگر F2 را قبل از F3 ببندی، `embedding_dimensions` رد می‌شود. راه‌حل: F2a را با بردارهای واقعی F3 کامل کن، یا از ابتدا جای بردار را با داده‌ی واقعی پر کن.

### F3 — ورود اسناد و بردارسازی (۲۲ نمره)

**بخش ۷:** manifest → hash → PDF (یکی تصویری و بدون متن ⇒ باید علامت بخورد، نه ساکت ایندکس شود) → استخراج عنوان/نسخه/بخش از RST → chunk با ۲۲۰ توکن و هم‌پوشانی ۴۰ → بازسازی `start/end` و آزمون hash → `chunk_id` پایدار و وابسته به (سند، نسخه، بازه، محتوا) → UPSERT بدون تکرار → artifact با fingerprint.

**بخش ۸:** بارگذاری مدل محلی، `batch encode` + L2-normalize، cosine صریح در برابر dot نرمال‌شده، baseline TF-IDF، hybrid با RRF، ذخیرهٔ BLOB در SQLite و بازخوانی دقیق، ACL پیش از top-k، ساخت context ≤۷۰۰ توکن، سنجش latency با embedding cache گرم.

- **خروجی**: `artifacts/chunks.jsonl`، جدول `documents`/`chunks` پر، `work/sec07_ingestion/`، `work/sec08_embeddings/`.
- **قبول وقتی**: خطای منشأ صفر، `chunk_id` دو اجرای متوالی یکسان، و `check_day3_db.py` روی `embedding_dimensions` سبز.

### F4 — ارزیابی و قفل (۱۰ نمره)

متریک‌ها در سطح سند: Recall@3، MRR@3، nDCG@3. پاسخ‌ناپذیرها از میانگین بازیابی حذف و جدا ارزیابی می‌شوند. انتخاب روش با MRR@3 روی dev و قاعدهٔ تساوی `lexical → dense → hybrid`. سپس **قفل**: ذخیرهٔ `config_hash` و `locked_at` در `artifacts/`. پس از قفل، ساخت فایل‌های test یک‌بار و بدون بازگشت.

- **خروجی**: `deliverables/test_predictions.jsonl`، `deliverables/answerability_predictions.jsonl`، گزارش ارزیابی ماشین‌خوان.
- **قبول وقتی**: ۳۰ خط در هر فایل، هر خط با `ranked_doc_ids` سه سند **متمایز**، و آستانه‌ای که با dev انتخاب شده (نه test).
- **قاعدهٔ سخت**: بعد از دیدن خروجی test هیچ پارامتری را عوض نکن؛ گزارش بده، برنگرد.

### F5 — مسیریاب عصبی (۱۰ نمره)

`05_Router` مستقل از بقیه است؛ اگر F3 طول کشید، این فاز را جلو بینداز. چهار مسیر، جداسازی با `template_group` (بررسی شد: صفر گروه مشترک بین splitها)، baseline قانون‌محور، `TF-IDF + LogisticRegression` با انتخاب `C` از {۰٫۱، ۱، ۱۰}، شبکهٔ PyTorch (۳۸۴→۶۴→۴ با Dropout=0.1)، آموزش با AdamW/lr=0.003/batch=32 و patience=10، تحلیل پوشش/دقت روی آستانه‌های ۰٫۵/۰٫۷/۰٫۹، fallback به `clarify`، و ablation حذف موضوع.

- **خروجی**: `work/sec10_router/` + checkpoint + model card.
- **قبول وقتی**: پارامترهای قابل آموزش با محاسبهٔ دستی جور باشد و `macro-F1` روی dev از baseline قانون‌محور بهتر باشد (یا تفاوتش توضیح داده شود).

### F6 — گراف LangGraph (۱۰ نمره)

`StateGraph` واقعی با state شامل `query, user, case, route, evidence, history, answer, trace` و بدون secret. گره‌ها: ورود/مالکیت → مسیریابی → ابزار (تاریخچه با owner check / پژوهش محدود به public یا tenant مجاز) → تولید → اعتبارسنجی استناد. baseline تولید، **استخراجی و قطعی** است (بدون LLM پولی): پاسخ باید از quote واقعی ساخته شود و claim ناسازگار رد شود.

- **خروجی**: `work/sec11_langgraph/` + trace قابل بازپخش.
- **قبول وقتی**: درخواست غیرمالک در trace هیچ `history`/`research` نداشته باشد، و ۳۰ حملهٔ `06_Robustness` با نشت صفر عبور کنند.

### F7 — یکپارچه‌سازی و تحویل (۸ نمره)

اتصال API به `SQLiteAdapter`، endpoint پاسخ با trace ID، چهار مسیر منفی (401/403/422/422)، idempotency سرتاسری، نمای HTML حداقلی RTL با escape، traceهای `07_Observability` (۸۰۰ trace، p50/p95)، `regression_gate.json`، قرارداد CI/CD، اجرای نهایی `check_day3_db.py`، و manifest تحویل با hash فایل‌های کلیدی.

- **خروجی**: `deliverables/` کامل + `artifacts/database_check.json` + گزارش نهایی سه‌دسته.
- **قبول وقتی**: هر چهار فایل بارگذاری آماده باشند و هیچ مسیر شخصی/رمز در آن‌ها نباشد.

## ۵. ترتیب پیشنهادی اجرا

```
هفتهٔ کاری ۱: F1  →  F2a (دیتابیس)  →  F2b (کلاینت)
هفتهٔ کاری ۲: F3 (chunk + بردار)  ‖  F5 (مسیریاب، موازی)
هفتهٔ کاری ۳: F4 (ارزیابی + قفل)  →  F6 (گراف)  →  F7 (یکپارچه‌سازی)
```

برآورد خام: F1 یک نشست، F2 سه نشست، F3 چهار نشست، F4 دو نشست، F5 دو نشست، F6 سه نشست، F7 دو نشست.

## ۶. هستهٔ مشترک

برای اینکه ۱۴۴ سلول کد تکراری نشوند، یک هستهٔ کوچک در `work/_common/` نگه می‌داریم:

| ماژول | نقش |
|---|---|
| `paths.py` | مسیر مطلق `datasets/`، `resources/`، `artifacts/` نسبت به ریشهٔ پروژه |
| `db.py` | `connect()` با `PRAGMA foreign_keys=ON` و `timeout`، helper برای UPSERT |
| `config.py` | بذر `20261015`، نام/نسخهٔ مدل، نسخهٔ prompt، `config_hash` |
| `textio.py` | خواندن JSONL/CSV و نوشتن artifact با hash |

نوت‌بوک همان ماژول‌ها را import می‌کند؛ کد هر سلول کوتاه می‌ماند و عددها تک‌منبع می‌شوند.

## ۷. نقطه‌های توقف اجباری

1. **قبل از F4:** هیچ فایل test ساخته نشود.
2. **در پایان F4:** `artifacts/lock.json` نوشته و commit شود؛ بعد از آن تغییر پارامتر = دور زدن قید تکلیف.
3. **قبل از F7:** `check_day3_db.py` باید `passed` باشد؛ نه بعد از آن.
4. **قبل از ارسال:** جست‌وجوی `TEST-ONLY-SECRET`، مسیر `C:\Users`، و هر رشتهٔ شبیه کلید در نوت‌بوک و JSON.
