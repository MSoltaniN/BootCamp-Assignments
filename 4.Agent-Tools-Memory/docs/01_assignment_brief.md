# صورت تکلیف — خلاصهٔ اجرایی

منبع: صفحهٔ تکلیف در سایت iCourse و `assignment/source/Day4/ASSIGNMENT.md` (این دو یکسان‌اند).

## شرح تکلیف

در این تکلیف معماری ایجنت و Workflow، مهندسی context، ابزارهای محدود و MCP واقعی، حلقهٔ محدود، حافظهٔ محفوظ، حافظهٔ پایدار و تأیید انسانی، مسیریابی، دفاع چندلایه، ارزیابی و انتشار کنترل‌شده را تمرین می‌کنی.

- **۱۲ بخش** و **۱۴۴ زیرسؤال**
- **۴۸ سؤال مفهومی** با ۲۴ نمره (بخش‌های ۱ تا ۴)
- **۹۶ سؤال عملی** با ۷۶ نمره (بخش‌های ۵ تا ۱۲)
- **جمع ۱۰۰ نمره**

## ساختار هر زیرسؤال

برای هر زیرسؤال با عنوان «زیرسؤال N.M» سه چیز نگه داشته می‌شود:

1. **کد انگلیسی** — با خروجی اجرا، داخل خود نوت‌بوک
2. **تحلیل فارسی** — راست‌به‌چپ (`<div dir="rtl">`)
3. **شواهد** — اعداد و فایل‌های تولیدشده

اگر ماژول جدا نوشتی، نسخهٔ آن را در ZIP شواهد هم بگذار.

## قاعدهٔ نمره‌دهی

| نوع سؤال     | ۶۰٪              | ۴۰٪         |
| ------------ | ---------------- | ----------- |
| مفهومی (۱–۴) | گزینهٔ منتخب     | دلیل انتخاب |
| عملی (۵–۱۲)  | روش + کد + خروجی | تحلیل       |

ایجنت تصحیح‌کننده، پاسخ‌ها را می‌خواند و **کد تو را اجرا نمی‌کند**. پس خروجی باید داخل نوت‌بوک دیده شود؛ صرفِ وجود کد کافی نیست.

## مرز اجرای پاسخ مرجع

سایت صریحاً اعلام می‌کند:

> SQLite، MCP و گراف در پاسخ مرجع واقعاً اجرا شده‌اند؛ تصمیم‌گیر مدل، هویت reviewer و لاگ‌های مقایسه fixture هستند و LLM زنده اجرا نشده است.

این جمله هم محدودیت را می‌گوید و هم مجوز می‌دهد: تو هم می‌توانی fixture داشته باشی، به شرطی که صریح نامش را ببری.

## پیام کلیدی برای شروع

سه جملهٔ آخر سایت تعیین‌کننده است:

1. `Day4_Code` و `Day4_Run_Output` را **خودت** بساز.

3. `SQLite`، `MCP` و گراف باید واقعاً اجرا شوند؛ فقط تصمیم‌گیر و reviewer می‌توانند fixture باشند.
