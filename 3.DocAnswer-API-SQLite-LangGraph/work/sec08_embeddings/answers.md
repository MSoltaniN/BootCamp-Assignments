| مشاهده                   | عدد     | توضیح                                    |
| ------------------------ | ------- | ---------------------------------------- |
| lexical سریع‌ترین است    | ۱٫۱ ms  | فقط یک ضرب ماتریس پراکنده، بدون مدل عصبی |
| dense ۱۳ برابر کندتر     | ۱۴٫۶ ms | کدگذاری پرسش با مدل، نه جستجو            |
| hybrid ≈ dense + lexical | ۱۶٫۷ ms | هر دو مسیر اجرا می‌شوند، پس جمع می‌شوند  |

**چرا cold جدا نگه داشته شد:** اولین فراخوانی مدل شامل بارگذاری وزن‌ها و ساخت حافظهٔ میانی است و ۱۵٫۲۲ ms شد، در حالی که warm ۱۱٫۵۴ ms است. اگر cold را داخل نمونه‌های p50 می‌ریختیم، عدد به‌طور مصنوعی بالا می‌رفت. برای اندازه‌گیری درست، ۳۰ پرسش **train** با کش گرم اجرا شد.

**نکتهٔ مهم:** این زمان‌ها روی CPU و برای ۱۲۸۶ بردارند. با ایندکس برداری (HNSW/IVF) یا GPU اعداد متفاوت می‌شوند؛ این اندازه‌گیری «هزینهٔ جستجوی دقیق در حافظه» است، نه یک SLA.

## محدودیت‌ها و مرز اجرا

- **واقعاً اجراشده:** hash ۱۱ فایل مدل، کدگذاری ۱۲۸۶ chunk با مدل واقعی، cosine در دو فرم، TF-IDF، RRF، ذخیره و بازخوانی BLOB، ACL، ساخت context، اندازه‌گیری زمان، رد ایندکس ناسازگار.
- **fixture:** چهار سیاست مصنوعی، بردارهای ذخیره‌شده در فایل SQLite (واقعی‌اند ولی مدل محلی است).
- **اجرانشده:** ایندکس برداری تقریبی (HNSW/IVF) — جستجو **دقیق** و خطی است؛ برای ۱۲۸۶ بردار کافی است. GPU و سرویس برداری.
- **عدد ۸٫۳ به جفت chunk0/chunk1 اشاره دارد**، نه به بهترین نتیجهٔ جستجو. جفت پرسش/chunk0 جدا گزارش شد (۰٫۰۸۹۶) تا دو چیز قاطی نشود.
- **زمان‌های ۸٫۱۱ به دستگاه بستگی دارند** و با عدد مرجع تطبیق سخت داده نمی‌شوند.
