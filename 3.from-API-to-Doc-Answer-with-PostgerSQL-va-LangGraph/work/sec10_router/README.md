# بخش ۱۰ — انتخاب مدل و ساخت مسیریاب عصبی (۱۰ نمره)

## چه چیزی ساخته می‌شود

مسیریاب چهارکلاسه روی `05_Router`، با سه baseline و یک شبکهٔ عصبی کوچک. داده مصنوعی است و جداسازی با `template_group` انجام شده؛ split آماده را دست نزن.

| ماژول | نقش |
|---|---|
| `split_audit.py` | توزیع کلاس/split و اثبات صفر بودن گروه مشترک بین splitها |
| `rules.py` | baseline قانون‌محور؛ قوانین فقط از نمونه‌های train |
| `linear.py` | `TF-IDF(1,2) + LogisticRegression` با انتخاب `C` از {۰٫۱، ۱، ۱۰} بر اساس macro-F1 dev |
| `features.py` | embedding ثابت مدل محلی به‌عنوان feature (شکل‌ها + norm؛ encoder آموزش نمی‌بیند) |
| `mlp.py` | شبکهٔ `384 → 64 → ReLU → Dropout(0.1) → 4` |
| `train.py` | AdamW، `lr=0.003`، `batch=32`، حداکثر ۶۰ epoch، patience=10 روی macro-F1 dev |
| `calib.py` | پوشش/دقت شرطی در آستانه‌های ۰٫۵/۰٫۷/۰٫۹ |
| `fallback.py` | آستانهٔ ثابت ۰٫۷ ⇒ مسیر `clarify` |
| `ablation.py` | پوشاندن ۱۰ موضوع با `TOPIC` و محاسبهٔ دوبارهٔ macro-F1 |

## ورودی

`datasets/05_Router/requests.csv` — ۴۸۰ ردیف: train ۳۲۰ (۳۲ گروه)، dev ۸۰ (۸ گروه)، test ۸۰ (۸ گروه)، چهار مسیر متعادل (۱۲۰ هر کدام)، **۰ گروه مشترک**.

## تعریف انجام‌شده

- تعداد پارامتر قابل آموزش با محاسبهٔ دستی جور است (۳۸۴×۶۴+۶۴ + ۶۴×۴+۴ = ۲۴۹۰۰).
- `C` و checkpoint فقط با dev انتخاب شده‌اند و پیش از دیدن test قفل شده‌اند.
- واژگان TF-IDF فقط روی train `fit` شده.
- `model_card.json` منشأ مصنوعی، split گروهی، معیارها، نسخهٔ encoder، دامنهٔ زبان و موارد استفادهٔ نامناسب را دارد.

## تله‌ها

- split تصادفی این داده را نابود می‌کند: مدل به‌جای مسیر، قالب را حفظ می‌کند.
- `unsupported` را با confidence پایین یکی نگیر؛ unsupported یک کلاس است، confidence پایین یک حالت.
- confidence خروجی softmax، احتمال کالیبره نیست؛ در ۱۰٫۸ صریح بنویس.
- در ۱۰٫۱۱ شبکه یا مدل را با dev بازآموزی نکن؛ فقط همان مدل ثابت را دوباره بسنج.
